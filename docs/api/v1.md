# v1 契约与运行语义

正式源：`packages/contracts/v1/openapi.json` 与相邻 JSON Schema；由 `scripts/export-contracts.py` 从边界模型导出。Java 序列化夹具在 `ContractTest` 生成，Python 集成测试再次以 Pydantic 与 JSON Schema 校验。LangGraph State 不出现在跨语言请求中。

## 公共 API（Java :8080）

| 接口 | 语义 |
|---|---|
| POST /api/v1/tasks | 必填 idempotency_key/input/limits；202 返回 TaskView |
| GET /api/v1/tasks/{task_id} | Task/Run、结果、错误与 Checkpoint 引用 |
| GET /api/v1/tasks/{task_id}/events?after=0 | sequence 递增；最多 500 条，after 排他 |
| POST /api/v1/tasks/{task_id}/cancel | 202，协作取消；已终态则幂等返回 |
| GET /actuator/health | 包含数据库健康 |

参数：message 1–4000 字符且非空白；values 1–100 个有限浮点数；max_steps 1–100，timeout_seconds 1–300。Java 创建入口要求显式 limits 和 values；内部 Runtime 可以使用契约默认值。unknown fields 拒绝。

## 内部 API（Python :8000）

- POST /internal/v1/executions：202，TaskExecutionRequest；固定 execution_id/idempotency_key/thread，同键异载荷 409。
- GET /internal/v1/executions/{execution_id}：ExecutionStatus。
- GET /internal/v1/executions/{execution_id}/events?after=0：ExecutionEvent[]。
- POST /internal/v1/executions/{execution_id}/cancel：202，持久化取消意图；允许先于提交到达。
- GET /health：进程存活，不等同于模型/数据库服务可用。

执行请求包含 v1、task_id、execution_id、idempotency_key、trace_id、request_id、checkpoint_thread_id、main-agent、input、limits。Java DTO 与 Python Pydantic 双侧验证。真实模型最终输出通过 ToolStrategy(AgentResult) 进行结构化调用，Pydantic 再次校验；不能用 Markdown 文本冒充有效结果。Runtime snapshot 的 result 结构为 summary、specialist（可 null）、specialist_error、answer。

事件类型：execution_started、agent_started、tool_started、tool_completed、agent_completed、execution_completed、execution_failed、execution_cancelled。Java 还追加 task_created/task_claimed/task_running/task_cancel_requested/task_succeeded/task_failed/task_cancelled。Runtime 序号与 Java 业务序号不同；原 Runtime 事件放在 payload，顶层有统一 task/execution/trace/version/time/sequence。

## 一致性与超时

- Java 幂等键当前作用域为受控开发环境（数据库唯一）；相同规范 DTO 载荷返回原 Task/Run/trace，冲突 409。没有实现用户/租户授权。
- Runtime 去重记录必须与 Checkpoint 数据一起保留；删除去重库后不能承诺不重复执行。
- Java HTTP 默认 2 秒，连接 2 秒。失败后有限在租约有效期内轮询；先 GET，404 才重发相同请求。无响应不判定 Python 已停止，也不生成新 Run。每轮固定延迟，P0 无指数退避。
- Java 租约默认 15 秒，仅在收到有效状态和事件后续租；Runtime 心跳表现为响应状态轮询。Run.heartbeat_at 是最近一次平台成功观察，不是 Worker 推送心跳。
- Runtime deadline 包含子进程启动，使用 monotonic；模型默认 30 秒且不自动重试。步骤预算跨主/子共享，模型调用和工具调用都消耗一步；递归限额另设兜底。
- 取消/完成由 Java 任务行锁决定：取消事务先写入时不再发布成功结果；完成先提交时取消不改变终态。Runtime cancel/finish 也事务串行化；预先取消标记阻止迟到执行。
- 租约过期会失败关闭且 fence 增加；晚到结果不能覆盖。旧 Worker 可能已做完只读计算，这不等于平台接受该结果。生产副作用需要额外执行凭证与幂等账本。
- Runtime 终态事件可能早于 Java 最终业务事件到达，消费者应以 Task 状态/最后 task_* 事件判断业务结果。

## 错误码

Java：INVALID_REQUEST(400)、TASK_NOT_FOUND(404)、IDEMPOTENCY_CONFLICT(409)、DATABASE_UNAVAILABLE(503)、INTERNAL_ERROR(500)。响应带 trace_id，X-Trace-Id 响应头；输入 trace 仅接受 1–80 个安全字符，否则生成 UUID。

内部传输：RUNTIME_OUTCOME_UNKNOWN / RUNTIME_UNAVAILABLE / EXECUTION_NOT_FOUND；运行：AGENT_FAILED / EXECUTION_TIMEOUT / WORKER_LOST；策略拒绝 TOOL_DENIED/DELEGATION_DENIED/STEP_LIMIT 最终归为 AGENT_FAILED；子 Agent 失败由 specialist_error=SUBAGENT_FAILED 表达，主 Agent 可返回降级结果。

HTTP/模型原始异常不向 API 暴露，防止包含凭证与输入。Python HTTP 参数错误使用 FastAPI 422；错误体尚未统一到 Java 外部错误格式，这属于内部适配限制。
